# ADR 0008 — 기능별 `docs/spec/<기능명>/` · 사람 기획 + AI 산출물(2026-10-31 제안)

> 템플릿 주: 하네스 원본 저장소에서 내린 결정을 근거로 옮겨 온 기록. 본문의 이슈 · PR 번호와 날짜는 원본 저장소 것이며, 이 저장소의 새 결정은 다음 번호부터 `0000-template.md` 꼴로 씀.

> 원본 규칙: `docs/spec/README.md` · `app-orchestrator` 0단계 4번 · 1단계 · `spec-writer` · `team-workflow` 2 · 3 · 5절.

## 결정

- 스펙을 `docs/spec/<이슈>-<기능명>.md` 로 한 줄로 쌓던 것을, 기능 하나 = 폴더 하나 `docs/spec/<기능명>/` 로 바꿈.
- 폴더 안 `artifacts/` 밖은 사람 기획(파일 수 · 이름 · 하위 폴더 자유). `artifacts/` 는 AI 산출물(스펙)만.
- 이슈 「참고」에 기획 위치를 적으면 spec-writer 가 그 아래 문서를 전부 읽음. 기능명은 그 폴더 이름.
- 산출물 경로는 이슈 「산출물」 칸에 사람이 지정. 비어 있으면 AI 가 제안하고 사람이 확인한 뒤 씀. 이미 있는 파일이면 그 파일을 고침.
- 사람 기획은 `docs/<기능명>` 브랜치로 이슈보다 먼저 develop 에 들어감. 닫힌 PR #3 의 `docs/planning/` 안을 대신함.

## 이유

| 무엇 | 이유 |
|---|---|
| 기능별 폴더 | 사람이 쓴 기획과 AI 가 만든 스펙이 한곳에 있어야 무엇을 보고 무엇을 만들었는지 비교 · 회고됨 — 하네스 목적(AI 활용 기록 공유)과 같은 방향 |
| 사람 문서 이름 자유 · 위치 지정 | 기획은 한 파일에 다 들어가지 않을 수 있음. 이슈가 위치만 가리키고 AI 가 그 아래를 다 읽으면 됨(사용자 피드백) |
| 산출물 경로를 사람이 지정 · 미지정이면 제안 후 확인 | 이슈마다 새 파일(판마다 문서)과 한 파일을 계속 고치는 방식은 경우마다 장단점이 있음. 고정 규칙 대신 사람이 고르게 함(사용자 피드백) |
| 영문 이름 | 브랜치 `<기능명>/main` 과 같은 이름이어야 AI 가 짝지을 표가 필요 없음 · guard 가 브랜치를 영문 꼴로만 받음 · 맥 ↔ 윈도우 한글 파일 이름 문제 |
| 이슈가 우선 | 기획 문서는 여러 이슈가 함께 보는 넓은 그림이고 이슈가 이번 범위 |

## 기계로 막는 것

- 없음. 「AI 는 사람 문서를 고치지 않음」 · 「산출물 미지정이면 확인 전 spec-writer 호출 금지」는 아직 약속.
- 센서 후보: spec PR 의 변경 파일이 `docs/spec/<기능명>/artifacts/` · `docs/api/openapi.json` 밖이면 잡음.
