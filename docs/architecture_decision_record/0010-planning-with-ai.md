# ADR 0010 — 기획 단계의 사람 ↔ AI 공동 기획(2026-11-02 제안)

> 템플릿 주: 하네스 원본 저장소에서 내린 결정을 근거로 옮겨 온 기록. 본문의 이슈 · PR 번호와 날짜는 원본 저장소 것이며, 이 저장소의 새 결정은 다음 번호부터 `0000-template.md` 꼴로 씀.

> 원본 규칙: `team-workflow` 2절 「사람 ↔ AI 공동 기획」 · `app-orchestrator` 「기획 흐름」 · `docs/spec/README.md`. ADR 0009 가 사람 기획을 `<기능명>/main` 으로 옮겼으나 그 단계에 AI 가 낄 자리를 두지 않아 생긴 빈 곳을 메움. 이슈 #11.

## 무엇이 있었나

「<기능> 을 같이 기획하자 · Android LLM 조사 · 화면 기획 조사」라는 요청에, 오케스트레이터가 이슈 게이트를 적용해 조사 · 기획을 하지 않고 `feature.yml` 칸을 되물음. 규칙대로였으나 사람이 기대한 것은 기획을 같이 다듬는 일이었음. 규칙을 보면 기획 단계는 전부 사람 몫이고(`docs/spec/README.md` 「AI 는 사람 문서를 읽기만 함」), AI 가 끼는 첫 지점은 이슈 번호 뒤였음.

## 결정

- **게이트가 가르는 선을 분명히 함** — 이슈 게이트가 막는 것은 **결정과 산출**(무엇을 만들지 · 작업 브랜치 · 스펙 · 구현)이지 **선택지와 제약을 드러내는 일**이 아님. 「같이 기획하자」 · 「기획 도와줘」 · 「후보 좀 보여 줘」는 되묻지 않고 기획 흐름으로 받음.
- **역할을 가름** — AI 는 제약 먼저 알리기 · 후보 표 내기 · 빈 곳 · 모순 짚기 · 사람이 고른 내용을 초안으로 받아쓰기까지. 사람은 무엇을 만들지 · 어느 후보를 고를지 · 화면 구성 결정 · 초안을 고쳐 커밋 · 푸시.
- **초안은 작업 트리에만** — AI 가 `docs/spec/<기능명>/`(`artifacts/` 밖)에 초안을 쓸 수 있게 하되, 커밋 · 푸시는 사람. ADR 0009 의 「에이전트는 `<기능명>/main` 에 커밋 · 푸시하지 않음」은 그대로.
- **브랜치는 사람이** — 이슈 번호 전이라 guard 가 에이전트의 `<기능명>/main` 생성을 막음. 에이전트는 만드는 법을 안내하고 기다림. 로컬 `git switch -c` 도 길로 인정(기존엔 GitHub 웹만 적혀 있었음).
- **기록 자리** — 기획 과정은 `_workspace/_planning/<기능명>/notes.md`(개인 · gitignore). 이슈 번호가 없어 `.claude/log/` 를 쓸 수 없는 동안의 자리이고, 이슈가 생기면 그 이슈 `log.md` 첫 절이 경로를 한 줄로 가리킴. 결과물은 `docs/spec/<기능명>/` 에 남음.

## 이유

| 무엇 | 이유 |
|---|---|
| 기획에 AI 를 들임 | 사람이 혼자 조사해 정한 뒤에야 주행 규제 · LLM 경계 7 · 개인정보 때문에 못 간다는 걸 알게 되는 낭비를 막음. 제약을 먼저 알고 고르는 편이 나음 |
| 그래도 고르기는 사람 | 무엇을 만들지를 AI 가 지어내면 이슈가 사람의 의도를 담은 작업지시서 구실을 못 함(ADR 0005 이슈 게이트의 취지) |
| 초안 쓰기는 허용 | 「고른 내용을 문서 꼴로 받아쓰기」는 결정이 아니라 받아쓰기. 사람이 읽고 고쳐 커밋하므로 주인은 그대로 사람 |
| 이슈보다 앞에 둠 | 사용자가 고른 흐름 — 기획이 서야 `feature.yml` 의 필수 칸(사용 장면 · 완료 조건)을 채울 수 있음. 기획 전에 이슈를 열면 그 칸이 빈 채로 남음 |
| 기록을 `_workspace/_planning/` 에 | `.claude/log/` 는 이슈 번호로 폴더를 만듦. 번호 없는 동안의 과정을 공유 기록에 섞으면 이슈 ↔ 기록 대응이 깨짐 |

## 곁다리로 고친 것 — 오케스트레이터 description 잘림

`app-orchestrator` 의 `description` 이 547자 중 **206자에서 잘려 로드되고 있었음**. 원인은 트리거 예시 `「이슈 #n 진행해줘」` 의 ` #` — YAML 평문 스칼라에서 공백 뒤 `#` 는 주석 시작. 그래서 「#n 이어서」 · 「#n PR 올려」 같은 트리거 문구가 실리지 않았음.

- 고침: 그 줄을 작은따옴표로 감쌈(547자 전부 실림을 확인).
- 재발 방지 센서 `check_skill_frontmatter.py` 추가 — frontmatter 가 열리고 닫히는가 · `name` · `description` 이 있는가 · 따옴표 없는 description 에 ` #` · `: ` 가 있는가. `sensors` 표와 CI `common` 잡에 등록.

## 기계로 막는 것

| 무엇 | 어떻게 |
|---|---|
| description 잘림 | `check_skill_frontmatter.py`(새 센서 · CI `common`) |
| 이슈 번호 없는 작업 브랜치 | guard 그대로(`_workspace/current` → `state.md` 없이 `<기능명>/…` · `bug/…` 금지) — 기획 흐름은 브랜치를 만들지 않으므로 영향 없음 |
| 에이전트의 `<기능명>/main` 푸시 | guard 그대로 |
| 「사람이 고르지 않은 내용을 초안에 넣지 않음」 | 약속(기계로 재지 못함) |
