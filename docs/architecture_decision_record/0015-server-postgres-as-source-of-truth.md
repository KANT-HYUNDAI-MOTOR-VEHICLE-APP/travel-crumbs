# ADR 0015 — 서버 PostgreSQL 이 데이터 원본 · 앱 Room 은 캐시(2026-11-07 제안 · 승인 대기)

> 원본 규칙: `server-architecture` 「데이터」 · `android-architecture` 「네트워크 · 세션 · 오프라인」 · `CLAUDE.md` 머리말. 이슈 #19. **ADR 0014 를 대체함.**

## 무엇이 있었나

- ADR 0014(2026-11-05 제안 · 승인 대기)는 「여행 기록 · 공유는 기기 안(Room)이 원본 · 서버는 로그인과 추천 근거 집계만 · 좌표는 서버에 없음」으로 정했음. 일정과 개인정보 부담이 이유였음.
- 2026-11-06: 데이터 표준 정의서 v0.2 · v0.35 와 ERD v0.2 가 develop 에 들어옴(#17). 모델이 25개 테이블 · 원본 위치점(`trip_route_point_dtl`) · 간소화 경로(`trip_route_dtl`) · 공유(`trip_share_dtl`)를 포함함 — 저장 위치가 문서에 적혀 있지 않아 Room 인지 PostgreSQL 인지 알 수 없었음.
- 2026-11-07: 사용자가 「PostgreSQL 로컬 디비로 할거야」로 정함. ADR 0014 의 전제가 깨짐.
- 0014 는 승인 전이었으므로 승인된 결정을 뒤집는 것은 아니지만, 하네스의 규칙 · 센서 · 심사 점검표가 이미 0014 를 따라 쓰여 있었음.

## 결정

- 데이터 원본은 **서버 PostgreSQL**(로컬 · docker compose). 여행 기록 · 경로 · 공유도 서버가 가짐.
- 앱 Room 은 **캐시 · 전송 대기 큐**. 캐시를 원본처럼 고쳐 쓰지 않음.
- **좌표는 서버에 있음**(원본 경로점 · 간소화 경로). 대신 넷을 기능 스펙에 적고 코드가 지킴 — 위치 동의 뒤에만 수집(정의서 R14) · 수집 범위 · 보관 기간 · 철회 · 탈퇴 시 삭제.
- 서버에 여전히 **없는** 것: 기어 · 속도 · VIN · Pleos 토큰 · 비밀번호.
- 로그인은 Pleos 계정 그대로. Pleos 아이디 값을 `user_mst` 에 보관하고 비밀번호는 받지도 저장하지도 않음.
- 내부 PK 는 시퀀스(`<단어>_no` · 정의서 R02) · 밖으로 나가는 식별자는 `_uuid`(정의서 R08).
- 삭제는 둘로 나눔 — 사용자가 지우는 것은 `deleted_yn` 논리 삭제 · 탈퇴와 Pleos 동의철회 웹훅은 하드 삭제(FK `ON DELETE CASCADE`).

## 이유

- 추천 · 공유가 이 앱의 중심인데, 기록이 기기에만 있으면 다른 사용자의 경로를 추천할 근거가 없음. 0014 는 「장소 id 만 집계」로 좁혔으나 정의서의 모델은 경로 · 장소 · 태그 · 유사도까지 다룸 — 집계만으로는 그 모델을 만들 수 없음.
- 저장 위치가 한 곳이어야 앱과 서버가 같은 테이블 · 컬럼 이름을 씀. 두 곳에 원본이 있으면 같은 여행이 기기마다 갈라짐.
- 좌표를 서버에 두는 대가는 개인정보 부담임 — 그래서 금지 대신 **조건**을 붙임. 동의 · 보관 기간 · 삭제는 Pleos 심사 「개인정보 · 보안」이 보는 항목이고, 계산으로 못 재므로 `pleos-reviewer` 5절이 맡음.
- PK 를 시퀀스로 바꾼 것은 정의서를 따른 것임(사용자 결정). 다만 연번을 그대로 밖에 내보내면 남의 기록 수 · 가입 순서가 드러나므로 외부 노출은 `_uuid` 로 가름 — 정의서 R08 과 같은 방향.
- 「즉시 삭제」를 논리 삭제로 때우면 동의철회 웹훅의 요구를 못 맞춤. 반대로 전부 하드 삭제로 하면 사용자가 실수로 지운 여행을 되돌릴 수 없음. 그래서 둘로 나눔.

## 버린 안

| 안 | 버린 이유 |
|---|---|
| ADR 0014 유지(기기 안 원본 · 좌표 금지) | 정의서의 모델을 만들 수 없음 · 추천 근거가 모자람 · 사용자가 PostgreSQL 로 정함 |
| 기기 원본 + 서버 사본 둘 다 | 같은 여행이 기기마다 갈라짐 · 동기화 규칙이 일정 안에 안 끝남 |
| 좌표를 서버에 두되 동의 · 보관 기간 없이 | 심사 「개인정보 · 보안」 반려 사유 · 철회 요구를 맞출 수 없음 |
| PK 를 UUID 로 유지(정의서를 고침) | 정의서의 모든 `_no` 칸 · ERD 를 고쳐야 함 · 사용자가 「무조건 정의서를 따른다」로 정함 |
| 전부 하드 삭제 · 전부 논리 삭제 | 앞은 되돌릴 수 없음 · 뒤는 동의철회 요구를 못 맞춤 |
