# ADR 0005 — 이슈 게이트: 이슈 없이는 기능 · 버그 작업을 시작하지 않음(2026-10-31 제안)

> 템플릿 주: 하네스 원본 저장소에서 내린 결정을 근거로 옮겨 온 기록. 본문의 이슈 · PR 번호와 날짜는 원본 저장소 것이며, 이 저장소의 새 결정은 다음 번호부터 `0000-template.md` 꼴로 씀.

> 원본 규칙: `CLAUDE.md` 「이슈 게이트」 · `app-orchestrator` 0단계 · `team-workflow` 1절.

## 결정

- 이슈 번호 없는 막연한 작업 요청에는 조사 · 기획 · 브랜치 · 구현을 하지 않음. 「깃헙 이슈를 만들 수 있도록 도와드릴게요」로 답하고 템플릿 칸을 하나씩 물음.
- 칸의 내용은 사람의 답만으로 채움. AI 가 조사 · 추측으로 기능을 지어내지 않음. 사람이 직접 아이디어를 청하면 후보만 보여 줌.
- guard 가 이슈 작업 폴더(`_workspace/current` → `state.md`) 없이 이슈 작업 브랜치를 만드는 명령을 막음.

## 이유

| 무엇 | 이유 |
|---|---|
| 게이트 | 「공모전 찾아서 구현해줘 · 브랜치도 알아서」 요청에 AI 가 공모전 조사 · 브랜치 생성부터 시작함(2026-10-30). 무엇을 만들지는 사람 결정이고, 이슈가 그 결정을 담는 작업지시서 |
| 글 규칙 + 기계 차단 | 글 규칙만으로는 지켜지지 않았음. 브랜치 생성은 모든 기능 · 버그 흐름의 첫 쓰기 동작이라 여기서 막으면 우회가 어려움 |
| `state.md` 를 증거로 | 오케스트레이터 0단계(이슈 확인 · 담당자 확인)를 거쳐야만 생김 |

## 기계로 막는 것

| 장치 | 막는 것 |
|---|---|
| guard(`.claude/guardrails/guard.py`) | `_workspace/current` 또는 그 폴더의 `state.md` 가 없을 때 `<기능명>/main · spec · impl · sync` · `bug/<n>-…` 를 만드는 `git switch -c/-C` · `checkout -b/-B` · `branch` · `branch -m/-c` · `worktree add -b` |
| 〃 | `bug/<n>-…` 의 번호가 지금 이슈 폴더 번호와 다를 때 |

- 이슈 없이 되는 브랜치: `harness/…` · `docs/…` · 그 밖의 이름.
- 시험: `.claude/guardrails/tests/test_guard.py` 의 `test_issue_gate`.

## 남은 것

- 웹 조사 · 파일 수정 자체는 기계로 막지 않음(질문 답변 · 한 줄 수정은 허용이라). 글 규칙에 맡김.
- `gh issue create` 를 사람의 「만들어」 없이 부르는 것도 약속만.
