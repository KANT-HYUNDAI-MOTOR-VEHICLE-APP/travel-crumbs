# ADR 0006 — 이슈별 AI 작업 기록(.claude/log) · 하네스 피드백도 이슈로(2026-10-31 제안)

> 템플릿 주: 하네스 원본 저장소에서 내린 결정을 근거로 옮겨 온 기록. 본문의 이슈 · PR 번호와 날짜는 원본 저장소 것이며, 이 저장소의 새 결정은 다음 번호부터 `0000-template.md` 꼴로 씀.

> 원본 규칙: `.claude/log/README.md` · `app-orchestrator` 「기록」 · 「하네스 피드백 흐름」 · `team-workflow` 1 · 2절 · `CLAUDE.md`.

## 결정

- 하네스의 목적을 **AI 활용 기록 공유 · AI 작업 방식 단일화**로 `CLAUDE.md` 에 명시.
- 이슈마다 `.claude/log/<n>-<짧은이름>/` — `log.md`(단계 기록) · `trace.md`(활동 요약). 오케스트레이터가 단계 끝마다 쓰고 그 단계의 작업 브랜치에 커밋. 이슈 댓글은 같은 내용의 알림.
- 하네스 변경도 `[하네스 피드백]` 이슈(`harness.yml`)로 시작 → `harness/<n>-<짧은이름>` → `harness:evolve` → PR → develop.
- 직접 프롬프트로 하네스를 바꾸는 것은 처음 환경 세팅 기간의 세팅 담당자만.

## 이유

| 무엇 | 이유 |
|---|---|
| `.claude/log/` 를 커밋 | 지금까지 기록은 `_workspace/`(개인 · gitignore)와 이슈 댓글뿐 — 저장소에 남는 공유 기록이 없었음. 사람마다 다른 방식으로 AI 를 쓰면 기록이 안 맞아 비교 · 회고가 안 됨 |
| 요약만 커밋(`trace.jsonl` 원본은 개인) | 원본은 크고 명령 원문이 들어 있음 · `trace_report.py` 가 비밀값을 가린 요약을 만듦 |
| 작업 브랜치에 함께 | `.claude/` 의 다른 파일과 달리 기록이라 harness 브랜치를 따로 거치면 이슈와 떨어짐 · 이슈마다 폴더가 달라 충돌 없음 |
| 하네스 피드백도 이슈 | 하네스를 바꾼 이유가 이슈 · log · ADR 에 남아야 다른 사람도 같은 방식을 따름 |

## 기계로 막는 것

| 장치 | 막는 것 |
|---|---|
| guard | `harness/<n>-…` 를 이슈 `<n>` 작업 폴더(`state.md`) 없이 만드는 것 · 번호가 지금 이슈와 다른 것(0005 의 이슈 게이트에 추가) |

- 번호 없는 `harness/<이름>` 은 환경 세팅 기간이라 아직 통과. 세팅이 끝나면 `guard.py` 의 이 예외를 지우는 하네스 피드백 이슈를 냄.
- `log.md` 를 단계마다 썼는지는 아직 약속 — PR 에 `.claude/log/<n>-…/` 가 없으면 잡는 센서가 다음 후보.
- 7단계 · 마무리는 커밋할 작업 브랜치가 없어 이슈 댓글로만 남음.
