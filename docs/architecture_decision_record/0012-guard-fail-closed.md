# ADR 0012 — guard 는 자기가 터져도 닫힌다(2026-11-04 제안)

> 원본 규칙: `.claude/guardrails/guard.py` · `.claude/README.md` 1절. 이슈 없음 — 처음 환경 세팅 기간의 세팅 담당자가 공식 문서 대조 중 발견.

## 무엇이 있었나

Claude Code 공식 문서(hooks)는 PreToolUse 훅의 종료 코드를 이렇게 읽는다 — **2 만 차단**, 0 은 통과, **그 밖의 코드는 「비차단 오류」라 명령이 그대로 실행된다**. 문서가 따로 경고문을 달아 둔 대목이다(「유닉스 관습으로는 1 이 실패지만 여기서는 아니다」).

`guard.py` 는 막을 때 2 를 돌려주고 있었으나, 두 갈래가 열려 있었다.

- 훅 입력(stdin) 이 JSON 으로 안 풀리면 `return 0` — 검사도 못 한 명령을 통과시킴.
- `inspect()` 안에서 예상 못 한 예외가 나면 파이썬이 역추적을 찍고 종료 코드 1 — 역시 통과. 화면에는 작은 훅 오류 표시만 남아 **막혔는지 아닌지 사람이 알 수 없다.**

`settings.json` 과 리뷰어 에이전트 둘에 `onFailure: "block"`(훅이 실패하면 막음)을 적어 뒀으나, 이 필드는 **Claude Code 2.1.295 이상**에서만 동작한다. 설치본은 2.1.268 이고, 문서상 모르는 필드는 **오류 없이 조용히 무시**되므로 그 세 줄은 지금 아무 일도 하지 않는다.

## 결정

- 울타리 장치를 두 갈래로 나누고 실패 방향을 고정한다 — **차단기는 fail-closed, 기록기는 fail-open.**
  - `guard.py`(차단기): 검사에 실패하면 막는다. 종료 코드 2 + 사람이 읽을 이유.
  - `trace_log.py`(기록기): 기록에 실패해도 작업을 막지 않는다(이미 그렇게 되어 있음 · ADR 0002).
- `guard.py` 의 `main()` 이 `Blocked` 뿐 아니라 **모든 예외**를 잡아 2 를 돌려준다. 깨진 훅 입력도 같다.
- 막는 길을 `block()` 한 함수로 모은다 — stderr 이유 · 활동 로그 · 종료 코드 2 가 늘 함께 간다.
- 명령이 없는 호출(`tool_input.command` 가 빔)은 그대로 통과. 닫는 것은 **검사 실패**일 때지 호출 전부가 아니다.
- `onFailure: "block"` 세 줄은 그대로 둔다 — 버전이 올라가면 바깥쪽 한 겹으로 다시 산다. 다만 **보장은 guard.py 쪽**이다.

## 이유

| 무엇 | 이유 |
|---|---|
| 예외 → 2 | 울타리가 비는 순간이 조용하면 안 됨. 틀려서 막는 쪽이, 모르고 미는 쪽보다 쌈 — 막히면 사람이 바로 알고 고칠 수 있음 |
| 버전에 안 기댐 | `onFailure` 는 CLI 버전에 달려 있고 두 사람의 설치본이 다를 수 있음. 저장소 안의 스크립트는 버전과 무관하게 같이 돎 |
| 차단기 · 기록기 구분 | 기록기까지 fail-closed 로 하면 로그 한 번 실패에 세션이 멈춤. 실패 방향은 그 장치가 무엇을 지키느냐에서 나옴 |
| 시험으로 고정 | 「고장 났을 때의 행동」은 평소 안 보이므로 회귀가 조용히 들어옴 — `test_guard.py` 의 `FailClosed` 가 매 CI 에서 잼 |

## 버린 안

| 안 | 버린 이유 |
|---|---|
| Claude Code 를 2.1.295+ 로 올리고 `onFailure` 에 맡김 | 두 사람의 설치본 · CI 환경을 버전으로 묶어야 함. 올려도 좋지만 그게 **보장**이 될 수는 없음 |
| 깨진 입력도 통과(종전) | 「검사 못 한 명령」과 「문제 없는 명령」을 같게 대우하는 것. 차단기의 뜻에 어긋남 |
| guard 안의 모든 호출 지점에 개별 try | 빠뜨리는 지점이 생김. 경계 한 곳(`main`)에서 받는 편이 셈이 쉬움 |

## 바뀌는 파일

| 파일 | 바뀌는 것 |
|---|---|
| `.claude/guardrails/guard.py` | `block()` 추가 · `main()` 이 모든 예외를 2 로 받음 · 모듈 설명에 fail-closed 명시 |
| `.claude/guardrails/tests/test_guard.py` | `FailClosed` 3 건(깨진 입력 · 검사기 고장 · 명령 없는 호출은 통과) |
