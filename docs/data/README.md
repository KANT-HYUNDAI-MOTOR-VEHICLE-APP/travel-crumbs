# docs/data — 데이터 표준 · 데이터 모델

테이블 · 컬럼 이름과 코드값의 **원본**. 앱(Room)과 서버(PostgreSQL)가 같은 용어를 쓰게 하기 위함.

| 파일 | 무엇 |
|---|---|
| `standard.md` | 데이터 표준 정의서 — **항상 최신판**. 명명 규칙 · 테이블 표준 · 공통 컬럼 · 표준 단어 · 도메인 · 용어 · 코드 사전 |
| `erd.md` | 논리 · 물리 데이터 모델(ERD) · 테이블 목록 · 제약조건 · 화면 ↔ 데이터 연결 |
| `archive/standard-v<판>.md` | 지난 판. 읽지 않음 — 「왜 바뀌었나」를 찾을 때만 |

판 번호는 **문서 첫 줄**에 있음. 파일 이름에는 넣지 않음 — 하네스의 스킬 · 에이전트 · 센서가 이 경로를 그대로 부르므로 판이 올라갈 때마다 참조가 깨지면 안 됨. 새 판이 나오면 지금 `standard.md` 를 `archive/standard-v<지금 판>.md` 로 내리고 새 판을 `standard.md` 로 올림.

## 읽는 법

| 누가 | 언제 |
|---|---|
| `spec-writer` | 스펙의 「데이터」 · 「API 계약 변경」 절을 쓰기 전 |
| `builder`(server) | 모델 · 스키마 · Alembic 리비전을 쓰기 전 |
| `builder`(app) | Room 엔티티 · DTO 이름을 짓기 전 |
| `structure-reviewer` | 서버 구조 리뷰(`server-architecture` 규칙 9) |

- **「결정」만 규칙으로 따름.** 정의서의 상태 칸은 결정 · 제안 · 미결 · 가안 네 가지. 「제안 · 미결 · 가안」에 걸리는 칸은 그대로 구현하지 않고 스펙의 「미확정」 표로 올려 사람이 정하게 함 — 초안을 확정인 양 굳히면 되돌리는 값이 커짐.
- **범위를 나눠 읽음.** 명명 규칙 · 테이블 표준 · 공통 컬럼(1 ~ 2절)은 통째로, 표준 단어 · 도메인 · 용어 · 코드 사전은 쓰려는 이름만 찾아 봄.
- **스펙에 판을 적음.** 스펙 첫머리에 `- 데이터 표준: v<판>` 한 줄 — 어느 판으로 만든 것인지 리뷰에서 보이게.
- **규칙을 여기서 베끼지 않음.** 스킬 · 에이전트 정의는 이 경로를 가리키기만 함. 같은 목록이 두 곳에 있으면 한 곳만 고쳐져 규칙과 센서가 어긋남.

이름 · 유형 단어 · 공통 컬럼은 `check_data_standard.py` 가 계산으로 잼(`sensors` 스킬). 센서가 재는 것은 리뷰어가 다시 세지 않음.

## 고치는 법

정의서 · ERD 는 **사람이 고침**. AI 는 읽기만 하고, 어긋나는 곳을 찾으면 스펙의 「미확정」 표나 리뷰 표로 올림. 정의서를 바꾸는 결정은 `docs/architecture_decision_record/` 에 남김(ADR 0016).

두 사람이 같은 절을 고치면 충돌함 — `team-workflow` 5절 「충돌 핫스팟」.
