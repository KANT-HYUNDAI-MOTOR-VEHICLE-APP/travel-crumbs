# docs/spec — 기능별 기획 · 스펙

사람이 쓴 기획과 AI 가 만든 스펙을 기능 하나에 폴더 하나로 모음. 무엇을 보고 무엇을 만들었는지 한곳에서 보이게 하기 위함.

## 구조

```
docs/spec/
  <기능명>/                 ← 브랜치 <기능명>/main 과 같은 이름
    (사람 문서)             ← 사람이 씀 · 파일 수 · 이름 · 하위 폴더 자유
    images/                 ← 시안 · 스케치(있으면)
    artifacts/              ← AI 산출물(스펙)만
```

예:

```
docs/spec/share/
  overview.md
  flows/invite.md
  images/share-sheet.png
  artifacts/share-link.md
```

- **기능명**: 영문 소문자 · 숫자 · `-` (`share` · `my-feature`). 브랜치 `<기능명>/main` 과 같게 — guard 가 브랜치 이름을 이 꼴로만 받고, 맥 ↔ 윈도우 사이에 한글 파일 이름이 깨질 수 있어서. 한글 기능 이름은 문서 첫 줄 제목에.
- **파일 · 폴더 이름**도 같은 꼴(영문 소문자 · 숫자 · `-`). 한글 · 공백 없이.

## 사람 문서

- `artifacts/` 밖은 전부 사람 몫. 한 파일에 다 넣지 않아도 됨 — 화면 · 흐름별로 나눠도 됨.
- 기능 브랜치 `<기능명>/main` 에 올림 — 사람이 GitHub 웹에서 develop 으로부터 브랜치를 만들고 그 브랜치에 직접 커밋(이슈보다 먼저). 기획 · 스펙 · 코드가 함께 움직이다 기능이 끝날 때 함께 develop 으로 들어감. 절차는 `team-workflow` 2절 「기능 브랜치에서 기획」.
- 기획이 바뀌면 같은 파일을 고침. 지난 판을 따로 두지 않음(git 이력이 있음).
- AI 가 사람 문서에 손대는 때는 하나뿐 — **기획 단계에서 사람이 고른 내용을 초안으로 받아쓸 때**(작업 트리에만 씀 · 커밋 · 푸시는 사람 · 고르지 않은 곳은 「미정」. 절차는 `team-workflow` 2절 「사람 ↔ AI 공동 기획」).
- 이슈가 생긴 뒤로는 읽기만 함. 기획과 다르거나 빈 곳은 산출물의 「미확정」 표에 올림 — 기획의 주인이 사람이어야 산출물이 무엇을 보고 만들어졌는지 분명해짐.
- 기획 과정(오간 후보 표 · 결정)은 `_workspace/_planning/<기능명>/notes.md`(개인 · gitignore)에 남음. 이슈 번호가 없어 `.claude/log/` 를 쓰지 못하는 동안의 자리이고, 이슈가 생기면 그 이슈 `log.md` 첫 절이 이 경로를 한 줄로 가리킴.

### 형식 — AI 가 읽기 좋은 순

| 형식 | AI 가 읽는 법 | 권장 |
|---|---|---|
| Markdown | 그대로 읽음 · PR 에서 바뀐 줄이 보임 | **가장 좋음** |
| 글자 PDF | 직접 읽음(한 번에 20쪽씩 · 그림도 봄) | 좋음 |
| png · jpg | 그림으로 읽음 | 화면 시안 · 스케치에 좋음 |
| pptx · docx · key · hwp | 직접 못 읽음 | **PDF 로 내보내서 넣기** |
| 스캔 PDF · 사진 찍은 문서 | 읽지만 글자를 잘못 읽을 수 있음 | 수치 · 문구는 Markdown 으로 옮김 |
| Figma 링크 | Figma 연결이 있으면 읽음 | 링크를 Markdown 에 적음 |
| Google Docs · Notion · Confluence(비공개) | 로그인이 필요해 못 읽음 | Markdown 또는 PDF 로 내보내 넣기 |

- 화면 문구는 「」, 표는 Markdown 표. 파일 하나 20MB 이하 — 영상 · 큰 원본은 링크로.

## 이슈에 적는 것

| 칸 | 꼴 | AI 가 하는 일 |
|---|---|---|
| 참고 | `기획: share/main · docs/spec/share/` · `기획: share/main · docs/spec/share/flows/` · `기획: share/main · docs/spec/share/overview.md` | 지정한 위치 아래 문서를 전부 읽음(`artifacts/` 는 빼고). 기능명은 이 폴더 이름을 씀 |
| 산출물 | `docs/spec/share/artifacts/share-link.md` | 그 파일에 씀. 이미 있으면 그 파일을 고침 |

- **산출물을 비워 두면**: AI 가 `docs/spec/<기능명>/artifacts/<짧은이름>.md` 를 제안하고 사람이 확인한 뒤 씀. 이미 있는 파일을 고칠지 새 파일을 만들지도 이때 사람이 정함.
- 이슈 본문과 기획 문서가 다르면 **이슈가 우선**(이번 범위).
- 「스펙 생략」이면 산출물 없음 — 이슈 본문을 스펙으로 씀.

## AI 산출물

- `artifacts/` 아래에만 씀 · spec-writer 가 쓰고 `<기능명>/spec` 브랜치에서 커밋 · PR 로 사람이 확인.
- 산출물 첫머리에 이슈 번호 · 읽은 기획 위치를 적음 — 어느 이슈가 무엇을 보고 만들었는지 남기기 위함.
- builder · 리뷰어는 이 산출물을 스펙으로 읽음.
