# 장소를 차량 내비 목적지로 설정(NaviHelper 길안내 연동)

## 1. 요약 (수정: 2026-11-05 시나리오 확정 반영)

- 정차 홈에서 #6 의 맨 위 영역(기록 상태 · 「이 장소 기록」) 아래 「가 볼 장소」 구역 = 사용자가 미리 고정해 둔 앞으로 갈 곳(최대 3곳 · 결정 기록 U16 · 장소 이름 · 주소)과 장소마다 「여기로 안내」 버튼 · 고정한 장소가 없으면 구역 제목 + 안내 한 줄. 그 아래 「장소 고르기」에서 앱 안 후보 장소(assets JSON 고정 값) 중 고정 · 해제 · 고정 목록은 기기 안에 저장되어 앱을 다시 켜도 남음.
- 버튼 한 번 터치 → NaviHelper 로 그 장소의 좌표 · 이름 · 주소를 기본 내비 앱에 넘겨 경로 안내 시작 · 시작 · 실패(짧은 이유)를 홈 상태에 남김 · 내비 서비스 미연결이면 버튼 비활성 + 연결 안 됨 문구. 안내가 시작되면 그 장소가 **현재 여행의 핀**으로 기록됨(기록 중일 때만 · U42). **「여기로 안내」 · 고정 · 해제는 정차 홈에서만** — 주행 · 모름이면 #6 의 주행 전용 화면이 그려져 두 구역 · 버튼 모두 없음(결정 기록 U35 · #6 D16).
- **영역 = app 하나** · `server/` 는 만들지 않음(결정 기록 U39 · 팀 확인 필요). 핀은 저장소 뒤에 남고 순서대로 읽을 수 있음 · 받는 쪽에 넘기고 장소별 안내 건수(추천 근거)를 조회 — 지금은 기기 안 **Mock**(시드 여행 2 ~ 3건에서의 출현 + 내 핀) · 서버는 5절 계약만 두고 후속 이슈. 로드맵 · 집계 · 추천 화면은 범위 밖. 기기 밖으로 나가는 데이터 없음 · 좌표는 기기 안 NaviHelper 로만 · 위치 수집 없음.

용어(수정: 2026-11-05 시나리오 확정 반영 · 결정 기록 U45)

travel-crumbs 는 여행 때 쓰는 앱 — 여행 중 목적지를 정하면 그 장소가 핀으로 박히고, 여행이 끝나면 핀들이 로드맵(타임라인)이 되어 공유됨 · 다른 사람의 여행지를 보고 내 여행에 참고함. #4 는 이 흐름의 「목적지를 정하는 입구」.

| 말 | 뜻 | 주인 |
|---|---|---|
| 가 볼 장소 · 고정 | 사용자가 미리 골라 둔 **앞으로 갈 곳**(후보 중 최대 3곳) · 「고정」 · 「고정 해제」로 바뀜 · 여행 기록이 아님 | #4 |
| 핀 | **진행 중인 여행에 속하는 목적지 기록**(여행의 한 점) — 「여기로 안내」로 안내가 시작되면 1건 · 칸 = 장소 id · 시각 · 여행 안 순서 | #4 가 남김 · 여행에 붙이고 로드맵으로 엮는 일은 #3 |
| 여행 · 기록 상태 | 여행 시작 · 종료 · 기록 중(RECORDING) / 일시정지(PAUSED) | #6 RecordingState(D1 · D2) · #3 |
| 로드맵 | 한 여행의 핀을 순서대로 엮은 타임라인 | #3(업무 3) |
| 공유 · 다른 사람 여행 | 로드맵 공유 · 다른 사람의 여행지를 보고 목적지로 씀 | 업무 4 · 지금은 Mock 시드 여행으로만 집계에 씀 |

- 결정 기록 U13 의 「핀 고정」은 리뷰 1 의 비유(대화방 상단 고정)였음 — 이 스펙에서 「고정」은 가 볼 장소에만, 「핀」은 여행 기록에만 씀. 사용자 화면 문구의 혼동 여부는 U24.
- #6 의 「이 장소 기록」(#3 연결 지점)은 지금 있는 곳의 경험 기록 · 핀은 정한 목적지의 기록 — 서로 다른 기록.

의존 · 범위 밖(수정: 2026-11-05 시나리오 확정 반영)

- 의존: **#6(앱 뼈대) impl 이 먼저 머지되고 #4 구현은 그 위에 올림** — 홈 틀(정차 · 주행 화면 전환 · 홈의 맨 위 영역 · 기능 구역 자리 · debug 카드 자리) · RecordingState(핀을 남길지 읽기만) · 주행 판정(기어 + CarUxRestrictions)은 #6 몫(결정 기록 U38).
- 이번에 하지 않는 것(참고): 서버 구현(`server/` · DB · 기록 수신 · 건수 조회 API — 5절 계약 · 4.5 · 6.1 을 따르는 후속 이슈) · 여행 시작 · 종료 · 핀을 여행에 붙이기 · 로드맵(#3 · #6) · 로드맵 공유 · 시드 여행 둘러보기 화면(업무 4) · 「장소 고르기」 후보의 장래 출처 = 다른 사람의 여행지 · 공유받은 여행(회의 4-6 「공유받은 여행을 목적지로」) — 지금은 후보 JSON 그대로 · 후보 저장소의 자료원을 바꿔 이어 붙임 · 위치 수집 — #6 의 RecordingState 를 위치 수집 쪽(성호)이 구독하는 별도 이슈 · 주행 전용 화면 배치(#6) · 주행 중 목적지 변경(음성 · #5).

- 「고정」 → 그 장소가 「가 볼 장소」 맨 아래(결정 기록 U19)에 바로 나타나고 기기 안에 저장. 「고정 해제」 → 「가 볼 장소」에서 바로 빠지고 남은 장소의 순서는 그대로.
- 길안내 요청 상태와 무관 — 요청 중에도 고정 · 해제할 수 있음. 요청 중인 장소를 해제해도 요청은 그대로 진행 · 결과 문구는 요청할 때의 장소 이름으로.

## 3. 상태

### 3.1 홈 UiState 에 더하는 칸 (수정: 2026-11-05 #6 답변 반영)

기존 칸(`drivingState` · `naviReady` · `navi` · `openedByGleoAction`)은 #6 이 홈을 다시 짤 때의 칸을 따름 — `drivingState` 는 #6 의 합성 판정 값(결정 기록 U37).

| 칸 | 뜻 | 처음 값 |
|---|---|---|
| `pinnedPlaces` | 「가 볼 장소」에 그릴 고정 장소 목록(고정 순서 · 장소마다 id · 이름 · 주소) · 기기 저장을 아직 못 읽었으면 「읽기 전」 — 좌표는 화면 상태에 넣지 않음(화면이 그리지 않으므로) | 읽기 전 |
| `candidates` | 「장소 고르기」에 그릴 후보 목록(후보 JSON 순서 · 장소마다 id · 이름 · 주소 · 고정 여부) | 후보 전부 · 고정 여부는 고정 목록을 읽은 뒤 채움 |
| `placesVisible` | 「가 볼 장소」 · 「장소 고르기」 두 구역을 그리나 — `drivingState` 가 PARKED 일 때만 참(바뀌기 전 `pickerVisible` 을 넓힘) | 거짓 |
| `canPinMore` | 고정 수 < 최대(결정 기록 U16) — 거짓이면 E8 표시 · 「고정」 비활성 | 참 |
| `routeRequest` | 마지막 길안내 요청 상태 — 대기 · 요청 중(장소 id) · 시작됨(장소 이름) · 실패(이유 코드) | 대기 |

- 바뀌기 전의 `places`(고정 값 전부) 칸은 `pinnedPlaces` · `candidates` 로 나뉨.
- 「여기로 안내」 버튼 활성 여부는 따로 칸을 두지 않고 `naviReady` · `routeRequest` 에서 정함 — 활성 = `naviReady` 이고 `routeRequest` 가 요청 중이 아님(구역은 `placesVisible` 일 때만 그려짐).
- 실패 이유 코드(앱 안 값 · 4.2): `NOT_CONNECTED` · `TOO_CLOSE` · `TOO_FAR` · `LOW_BATTERY` · `ROUTE_NOT_FOUND` · `TIMEOUT` · `REQUEST_FAILED`.
- 사용자 행동은 ViewModel 메서드 셋 — 「여기로 안내」(장소 id) · 「고정」(장소 id) · 「고정 해제」(장소 id). 셋 다 `drivingState` 가 PARKED 가 아니면 무시. 결과는 이벤트가 아니라 상태 칸으로(android-architecture 규칙 5).
- 고정 목록의 단일 출처는 기기 저장을 감싼 저장소 — ViewModel 은 그 흐름을 받아 `pinnedPlaces` · `candidates` · `canPinMore` 를 만듦(화면에서 따로 들고 있지 않음).

- 이미 안내 중일 때 새 요청 = 목적지 바꾸기(Pleos 문서: `requestRoute` 는 목적지 설정 · 변경 · 재설정에 씀). 경유지 · 전체 코스 재안내는 만들지 않음.

### 4.2 내비 오류 → 실패 이유 (수정: U5 사람 결정 반영)

내비 오류 코드는 Pleos 문서 「목적지 설정」에 값 목록이 없어, 저장소가 쓰는 SDK(navi-data 3.0.4)의 `NaviErrorCode` 값 이름을 근거로 함. 값의 뜻 설명은 문서에 없어 값 이름에서 읽은 뜻으로 아래 표대로 확정 · 표에 없는 값은 일반 문구로 떨어짐(결정 기록 U5).

| 내비 오류 코드 | 실패 이유 코드 | E3 이유 문구 |
|---|---|---|
| `CAUSE_SEARCH_ROUTE_TOO_SHORT_DISTANCE` | `TOO_CLOSE` | 「너무 가까운 곳이에요」 |
| `CAUSE_SEARCH_ROUTE_OVER_DISTANCE` | `TOO_FAR` | 「너무 먼 곳이에요」 |
| `CAUSE_LOW_BATTERY` | `LOW_BATTERY` | 「배터리가 부족해요」 |
| `CAUSE_SEARCH_ROUTE` · `CAUSE_SEARCH_TRIP` · 그 밖의(새로 생긴) 값 | `ROUTE_NOT_FOUND` | 「경로를 찾지 못했어요」 |

- 앱 쪽 실패: 미연결 `NOT_CONNECTED` · 응답 없음 `TIMEOUT` · 호출 예외 `REQUEST_FAILED`.

LLM · Pleos 호출 없음(`app/llm/` · `app/auth/pleos/` 는 그 이슈에서도 만들지 않음 — 결정 기록 U28). 첫 Alembic 리비전에 아래 테이블.

공통

- 인증: `Authorization: Bearer <우리 서버 액세스 토큰>`(server-architecture 「세션」 — PyJWT HS256 · 클레임 `sub` = `users.id` · `ver` = `token_version` · `exp` · 서버는 서명 · 만료 · `ver` 대조 · 발급은 #1 로그인 · 결정 기록 U28). 두 경로 모두 필요.

- 요청 본문 · 쿼리에 userId 칸 없음(규칙 4) · 정의 밖 칸이 오면 422 — 좌표 · 이름 등이 들어오지 못하게.

| 경로 | 메서드 | 요청 | 성공 응답 | 오류 |
|---|---|---|---|---|
| `/navigation-starts` | POST | 본문 `NavigationStartIn` — `placeId`(문자열 · `^[a-z0-9][a-z0-9-]{0,63}$`) · `startedAt`(date-time · 시간대 필수) | 201 `NavigationStartOut`(새로 받음) · 200 `NavigationStartOut`(같은 계정 · placeId · startedAt 이 이미 있음 — 기존 행 그대로) | 401 `UNAUTHENTICATED`(토큰 없음 · 만료 · 위조 · 지워진 계정) · 403 `CONSENT_REQUIRED`(결정 기록 U31 — #1 의 `consents` 가 생긴 뒤 켬) · 422 `VALIDATION_FAILED`(꼴 위반 · 정의 밖 칸 · 시간대 없음) · 422 `STARTED_AT_OUT_OF_RANGE`(서버 시각 + 5분보다 늦음 · 보관 기간 365일보다 오래됨) |
