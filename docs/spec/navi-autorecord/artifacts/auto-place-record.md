## 1. 요약 (수정: 도착 뒤 재출발) (수정: 3판 리뷰)

- 기록 중(RECORDING)인 여행에서 운전자가 **차량 내비 앱에서 직접** 시작한 안내가 **목적지에 도착**하면 그 도착(목적지 이름 · 주소 · 좌표 · 도착 시각)을 기기 안 「기록 대기」로 기억 → 그 뒤 **차를 다시 출발시킬 때**(도착 뒤 정차(P)를 거쳐 처음 주행으로 바뀜 · 3.4) 현재 여행의 장소 1곳(`trip_place_dtl` · `draft_yn = Y` · `recorded_at` = 도착 시각)으로 자동 기록. 예외 둘: 여행 종료 직전 · 머무는 동안 수동 「이 장소 기록」을 누르는 순간엔 대기를 먼저 확정. 안내 시작 때는 기록하지 않음 · 취소 · 도착 못 한 목적지 · 놓친 도착 · 도착 뒤 24시간 지난 대기는 기록 안 함.
- 위치 수집 동의(`LOCATION_COLLECT`)가 있을 때만 · 현재 여행 장소(수동 「이 장소 기록」 포함)와 100 m 안이면 한 번만 · 이 앱이 요청한 안내(추천 「안내 시작」 · 길안내 입구)는 기존대로 핀만(이유 3.6) · 중간에 들른 곳은 지금처럼 수동 「이 장소 기록」(장소 순서 = 기록 순). 위치 동의 철회 때 사람이 고치지 않은 자동 이름도 비움(3.9).
- 확정은 주로 주행으로 바뀌는 순간이라 화면 알림 · 입력 없음(장소 수만 늘어남) · 정차 뒤 「이어서 쓰기」 → A-03 으로 이름 · 태그 · 메모. 서버 · API · DB 표 · 표준 단어 · 권한 변경 없음. 「재출발」 신호 = 이미 읽는 기어 신호(시동 신호는 SDK 공개 API 에 없고 AAOS 경로는 새 권한 · N1).

| M1 | 상시 리스너가 사용자가 내비에서 직접 시작한 안내의 `onRouteStarted` **와 `onDestinationArrived`** 를 받나 — 앱이 앞 · 나눔 화면 옆 칸 · 뒤 · 얼림 각각에서 | 에뮬레이터: 여행 기록 중 → 내비에서 목적지 검색 · 「안내 시작」 → 모의 주행(SIMULATION_GUIDING) 또는 GPX 로 도착 → 앱 로그(콜백 이름만) | 도착 알림을 못 받으면 구현을 멈추고 스펙 4판(N12) |
| M2 | 직접 시작 때 `onRouteStarted` 가 오는 때(경로 선택 화면 vs 「안내 시작」 뒤) · 그때 목적지 조회가 되나 | 같은 실측 | 안내 시작 전이면 그 순간 목적지 조회가 안 될 수 있음 → 3.3 「목적지 모름」 행 |
| M3 | 재탐색 · 경로 옵션 변경 · 경유지 추가 때 `onRouteStarted` 가 다시 오나 | 에뮬레이터 GPX 이탈 · 옵션 바꾸기 | 와도 같은 목적지면 「진행 중 안내」 기억만 새로 씀 · 대기 유지(3.3 · 3.4) |
| M4 | 얼림이 길 때 쌓인 알림(도착 · 기어)이 버려지나 · 늦게 오면 순서가 지켜지나 | 내비 앞 5분 이상 → 도착 · P · D → 앱 복귀 | 버려지면 그 도착은 기록 안 함(놓친 도착) · 늦게 오면 도착 시각 = 받은 때(N7) |
| M5 | `poiId` · `poiSubId` · `poiProvider` 에 실제 값이 오나 | 조회 결과 칸 비었나 여부만 로그(값 없음) | 이번엔 저장 · 판정에 쓰지 않음(N5) |
| M6 | 도착 알림의 이름(`DestinationArrivedInfo.name`)이 시작 때 목적지 조회의 이름(`DestinationInfo.name`)과 같은 글자인가 | 같은 실측(이름 같음 여부만 로그 · 값 없음) | 다르면 「진행 중 안내 목적지가 하나뿐이면 그것」으로 맞춤(N8) |
| M7 | 도착 판정 반경 · 도착 알림 뒤 내비 모드(안내 끝 · 자동 종료 여부) | 같은 실측 | 기록에는 영향 없음 · 보고서에만 |
| M8 | 경유지가 있는 안내에서 경유지 도착 때 `onDestinationArrived` 도 오나(`onWayPointArrived` 만 오나) | 내비에서 경유지 1개 추가 뒤 모의 주행 | 경유지 도착이 `onDestinationArrived` 로 오면 목적지 이름 대조(3.3)로 걸러짐 |
| M9 | 기어 P → D 를 Virtual Console 로 바꿀 때 앱이 PARKED → DRIVING 을 받는가(앱 앞 · 얼림) | Virtual Console Motion → Gear | 받지 못하면 「재출발」 판정 불가 → N1 다른 후보 |
| M10 | 에뮬레이터 · 실차에서 시동 끔 → 켬 때 앱 프로세스가 살아남는가(대기 전원 상태) · 끝나는가 | 에뮬레이터 콜드 부트 · 실차는 사람 확인 | 끝나면 다음 앱 열림 때 대기 처리(3.4 「앱 새로 시작」 행) |
| M11 | 도착 알림이 차가 움직이는 중(D)에 오는지 · 정차(P) 뒤에 오는지 | 실측 | P 뒤에 오면 「도착 뒤 PARKED 를 봄」 조건(3.4)은 다음 P 를 기다림 → 시험 T22 확인 |

## 2. 화면 (수정: 도착 뒤 재출발 — 확정이 주행 전환 순간이라 정차 한 줄 안내를 뺌)

새 화면 없음 · 새 문구 없음. 자동 기록은 화면과 무관하게 앱 안에서 일어나고, 결과는 기존 화면의 「장소 수」 · 「이어서 쓰기」 띠 · A-03 시트 · 장소 목록으로 보임. 「기록 대기」(도착 ~ 재출발 사이)는 화면에 보이지 않음(N10).

### 2.1 기록 칸(정차 홈 · 진행 중 여행) (수정: 도착 뒤 재출발) (수정: 3판 리뷰 — 수동 기록 때 먼저 확정)

| 요소 | 자동 기록 뒤 |
|---|---|
| 맨 위 영역 장소 수(「장소 %1$d곳」) | +1 — 「이 장소 기록」과 같음(대기 중엔 늘지 않음) · 수동 「이 장소 기록」 때 대기가 먼저 확정되면 +2(대기 + 수동 · 3.4) |
| 한 줄 안내 | 기존 수동 기록 안내만(「위치를 저장했어요 · 태그는 정차 후에」 등) · 자동 확정만을 위한 안내 없음 |
| A-03 시트 | 자동으로 열지 않음 · 수동 기록 때 정차면 기존처럼 **수동 장소**의 시트가 열림(먼저 확정된 자동 장소가 아님) |
| 「이어서 쓰기」 띠 | 2.3 규칙대로 남은 경우 기존 띠 「작성 중이던 내용이 있어요」 · 「이어서 쓰기」 그대로 |

### 2.2 주행 화면(A-02) (수정: 도착 뒤 재출발)

| 요소 | 자동 기록 뒤 |
|---|---|
| 장소 수 | +1(화면이 앞이면 바로 · 아니면 다음에 보일 때) |
| 한 줄 안내 · 팝업 · 소리 · 화면 전환 | 없음(완료 조건 「주행 중 화면 알림 · 입력 없음」) |
| 「내비 안내」 카드 · 버튼 4개 | 그대로 |

### 2.3 「이어서 쓰기」 띠 → A-03 장소 기록 · 태그 시트 (수정: 도착 뒤 재출발 — 기록 시각 = 도착 시각) (수정: 3판 리뷰 — 칸엔 장소 번호만)

- 자동 기록 1건마다 「이어서 쓰기」 칸에 그 장소를 남김 — **칸이 비어 있을 때만**(이미 작성 중 내용 · 다른 장소가 있으면 덮어쓰지 않음 · N6). 한 번에 여러 건이 확정되면 가장 이른 도착 1건만. 수동 기록 때 먼저 확정한 대기는 칸에 남기지 않음(수동 기록이 기존 규칙대로 칸을 씀).
- 칸에는 **장소 번호만**(기존 꼴 · F26) — 이름 · 좌표 · 주소를 칸에 복사하지 않음. 그래서 철회 때 칸은 따로 비울 것이 없음(3.9).
- 정차 뒤 띠의 「이어서 쓰기」 → 기존 A-03 시트가 그 장소로 열림:

| 요소 | 값 |
|---|---|
| 제목 | 「이 장소를 기록했어요」(기존) |
| 기록 시각 | 「기록 %1$02d:%2$02d」 = **도착 시각**(`recorded_at` · 4.1 · N7) |
| 장소 이름 칸 | 내비 목적지 이름(고칠 수 있음) · 비었으면 주소에서 만든 처음 값 · 둘 다 없으면 빈 칸 |
| 태그 · 메모 · 「건너뛰기 · 나중에」 · 「저장」 | 기존 그대로 |

### 2.4 장소 목록(A-05 로드맵 검토 · A-08 내 로드맵 상세)

- 자동 기록 장소는 「이 장소 기록」 장소와 **같은 모양**(출처 표시 없음) — 순서 = 기록 순(확정 순 · N9) · 이름 · 「미완성」 표시(`draft_yn = Y` 동안) · 「+ 태그 달기」 → A-03.

### 2.5 주행 · 정차 · 모름 (수정: 도착 뒤 재출발)

| 판정 | 도착 → 대기 | 대기 → 확정(재출발) | 화면 |
|---|---|---|---|
| 정차(PARKED) | 함(3.3 조건) | 하지 않음 — 「도착 뒤 PARKED 를 봄」만 표시(수동 기록 · 여행 종료 예외는 3.4) | 변화 없음 |
| 주행(DRIVING) | 함 | PARKED 를 본 대기가 있으면 확정 | 장소 수 +1 · 안내 없음 · 띠는 정차 뒤 |
| 모름(UNKNOWN) | 함 | **하지 않음**(재출발로 보지 않음 · N2) | 변화 없음 |

화면 표시는 주행처럼 다루는 「모름」을, 확정 판정에서는 「재출발 아님」으로 다룸 — 잘못 확정(가지 않은 곳)보다 늦은 확정(다음 PARKED → DRIVING · 여행 종료)이 안전.

## 3. 상태 (수정: 도착 뒤 재출발 — 전체 다시 씀) (수정: 3판 리뷰 — 3.3 · 3.4 · 3.6 · 3.7 고침 · 3.8 · 3.9 추가) (수정: 4판 리뷰 — 3.2 · 3.3 · 3.6 · 3.8 「이 앱 요청」 판정)

### 3.1 UiState 칸

| 화면 | 칸 | 변경 |
|---|---|---|
| 기록 칸(`HomeUiState`) | `placeCount` · `message` | 그대로(값이 자동 기록으로도 늘어남 · 새 메시지 종류 없음) |
| 주행 화면(`DrivingUiState`) | `placeCount` | 그대로 · 새 칸 없음 |
| 앱 틀(`AppShellUiState`) | `unfinishedInputAvailable` | 그대로 · 새 칸 없음 |

화면 밖 상태(앱 수명 · 화면이 그려지지 않아도 이어짐):
- **진행 중 직접 안내(메모리)** — 시작 알림 때 목적지 조회로 얻은 목적지(이름 · 주소 · 좌표) 1건 · 「직접 시작」으로 분류된 것만(3.6). 새 시작 알림 · 취소 알림 때 바뀌거나 지워짐. 프로세스가 끝나면 사라짐(그 안내의 도착은 기록 안 함 · 3.5).
- **기록 대기(기기 안 저장)** — 4.2 꼴 · 시동 꺼짐 · 프로세스 종료 · 얼림을 넘김.
- **자동 이름 원본(기기 안 저장)** — 3.9 · 4.2 · 철회 때 「사람이 안 고친 자동 이름」을 가리는 데만 씀.
- 좌표 · 주소 · 이름은 화면 상태에 넣지 않음.

### 3.2 판정에 쓰는 상태

| 상태 | 값 | 출처 |
|---|---|---|
| 여행 기록 상태 | RECORDING · PAUSED · 진행 중 여행 없음 · COMPLETED · CANCELED · INTERRUPTED · 못 읽음(한도 `AppConfig.RECORDING_STATUS_READ_TIMEOUT_MILLIS`) | 기존 기록 상태 단일 출처 |
| 위치 수집 동의 | 동의함 · 동의 안 함(이력 없음 · 거부 · 철회) · 못 읽음 | 기존 동의 이력 최신 행 |
| 내비 연결 | 연결됨 · 미연결 | 기존 |
| 주행 판정 | PARKED · DRIVING · UNKNOWN | 기존 합성 판정(F22) — 앱 틀의 `!= PARKED` 판정이 아님(F27) |
| 이 앱 요청(4판 리뷰) | 「앱 요청과 같음」 참 · 거짓 — 참 = 내부 요청 칸(요청 중 · TIMEOUT 뒤 기억 중 X) 또는 시작됨 뒤 60초 안의 X(3.6) · 오래 남는 상태 흐름의 시작됨 · 실패는 보지 않음 | 기존 길안내 요청 입구의 읽기 전용 질의(3.8) |
| 진행 중 직접 안내 | 없음 · 목적지 D(이름 · 주소 · 좌표) | 3.1 |
| 기록 대기 | 0 ~ `AppConfig.AUTO_RECORD_PENDING_MAX_COUNT`(5)건(4.2) | 3.1 |
| 현재 여행의 장소 | 지우지 않은 장소 좌표(핀은 4판부터 판정에 쓰지 않음 · 3.6) | 기기 |

### 3.3 사건별 처리 — 시작 · 도착 · 취소 (수정: 3판 리뷰 — 한 번에 하나씩 · 같은 목적지 재시작)

- **사건은 들어온 순서대로 한 번에 하나씩 끝까지 처리**(3.3 · 3.4 의 모든 사건 · 주행 판정 변화 · 수동 기록 · 여행 종료 · 철회 포함). 시작 알림 처리(조회 전 `AppConfig.NAVI_QUERY_SETTLE_DELAY_MILLIS` 1.5초 기다림 + 목적지 조회 · 한도 `AppConfig.SDK_CALL_TIMEOUT_MS`)가 끝나기 전에 도착 알림이 오면, 도착 알림은 시작 처리가 끝난 뒤(진행 중 직접 안내가 정해진 뒤) 처리.
- 위에서부터 처음 맞는 행 하나만.

| 사건 | 조건 | 결과 | 조회 |
|---|---|---|---|
| 시작 알림(`onRouteStarted`) | 여행 ≠ RECORDING · 동의 ≠ 동의함 · 미연결 | 진행 중 직접 안내 = 없음 | 없음 |
| 시작 알림 | 안내 중 아님 · 조회 실패 · 한도 지남 · 좌표 쓸 수 없음(범위 밖 · (0, 0)) | 진행 중 직접 안내 = 없음(목적지 모름 · 그 안내의 도착은 기록 안 함) | 안내 상태(+ 목적지) |
| 시작 알림 | 목적지가 이 앱 요청과 같음(3.6 — 내부 요청 칸 또는 시작됨 뒤 60초 창 · 4판 리뷰) | 진행 중 직접 안내 = 없음(핀은 기존 규칙) | 함 |
| 시작 알림 | 그 밖 | 진행 중 직접 안내 = 목적지 D(재탐색 · 같은 목적지 재시작이면 같은 D 로 덮어씀) · 3.4 「새 시작 알림」 행 적용 | 함 |
| 취소 알림(`onRouteCancelled`) | — | 진행 중 직접 안내 = 없음(취소한 목적지는 기록 안 함) · 이미 있는 기록 대기 · 장소는 그대로 | 없음 |
| 도착 알림(`onDestinationArrived`) | 진행 중 직접 안내 = 없음 | 기록 안 함 | 없음 |
| 도착 알림 | 여행 ≠ RECORDING · 동의 ≠ 동의함 | 기록 안 함 · 진행 중 직접 안내 = 없음 | 없음 |
| 도착 알림 | 도착 이름 ≠ D 의 이름(앞뒤 공백 제거 비교 · M6 · N8) | 기록 안 함(경유지 · 다른 안내 도착일 수 있음) | 없음 |
| 도착 알림 | 그 밖 | **기록 대기 1건 추가**(D 의 이름 · 주소 · 좌표 · 여행 번호 · 도착 시각 = 알림 받은 때 · 「PARKED 봄」 = 아니오) · 진행 중 직접 안내 = 없음 | 없음 |
| 경유지 도착(`onWayPointArrived`) · `onRouteEnded` · `onDestinationChanged` | — | 아무것도 안 함(N11 · F8) | 없음 |

- 도착 알림 때는 조회하지 않음 — 도착 뒤엔 안내가 끝나 목적지 조회가 비거나 다를 수 있음 · 좌표는 시작 때 얻어 둔 값(F19).
- 이름은 `DestinationArrivedInfo.name` 이 아니라 시작 때 조회한 `DestinationInfo.name` 을 씀(완료 조건 「이름 · 주소 · 좌표는 내비의 목적지 정보에서」).

### 3.4 확정(재출발) · 폐기 (수정: 3판 리뷰 — 24시간 만료 · 같은 목적지 재시작 유지 · 수동 기록 때 먼저 확정 · N3 확정 · 계정 전환)

「재출발」 = **도착 뒤 주행 판정 PARKED 를 한 번 본 다음 처음 DRIVING 으로 바뀜**(기어 P → R/N/D 또는 주행 규제 · F22 · N1 · N2).

기한 두 가지(둘 다 `AppConfig` 한 곳 · 받은 때 = 도착 알림을 앱이 받은 때):
- `AppConfig.AUTO_RECORD_PARK_WAIT_MILLIS` = 10분 — 「PARKED 아직」인 대기만. 도착 뒤 이 안에 PARKED 를 못 보면 지나친 것으로 보고 폐기.
- `AppConfig.AUTO_RECORD_PENDING_MAX_AGE_MILLIS` = 24시간 — **모든 대기**(PARKED 봄 포함)의 절대 만료. 도착 시각 + 24시간이 지나면 어떤 사건보다 먼저 폐기. 10분 기한을 넘겨 「PARKED 봄」이 된 대기(앱 새로 시작 등)도 여기서 끝남.
- 확인하는 때: 앱 새로 시작(맨 먼저) · 대기 추가 · 주행 판정 변화 · 수동 기록 · 여행 종료 — 각 처리의 첫 단계로 24시간 만료분을 지운 뒤 진행. 따로 도는 주기 작업 없음.

### 3.5 놓친 도착 · 중복 (수정: 도착 뒤 재출발 — 옛 「놓친 시작 되찾기」를 바꿈)

- **놓친 도착은 기록 안 함** — 앱이 얼려진 동안 쌓인 도착 알림을 얼림이 풀릴 때 받으면 그때 처리(M4) · 프로세스가 끝나 잃었으면 되찾지 않음. 조회로 「도착으로 끝났는지」를 알 수 없음(F18) · 현재 위치로 짐작하지 않음. 화면 복귀 · 재연결 때 목적지 조회는 하지 않음 · 주기 조회 없음.
- **진행 중 직접 안내를 모르는 도착**(시작을 놓침 · 프로세스 다시 시작)은 기록 안 함 — 도착 알림에 좌표가 없어 중복 판단 · 기록을 할 수 없음(F17).
- **중복**: 확정 때 현재 여행의 모든 장소(수동 「이 장소 기록」 포함)와 좌표 100 m(기존 「목적지 같음」 반경 `AppConfig.ROUTE_MATCH_RADIUS_METERS` 재사용). 같은 목적지를 여러 번 도착해도 하나 · 도착 뒤 수동으로 남긴 곳(100 m 안)은 대기를 폐기. 수동 「이 장소 기록」 자체는 이 판단의 대상이 아님(수동은 막지 않음).

### 3.6 이 앱 요청 안내와 구분 (수정: 3판 리뷰 — 이유 명시 · 사람 결정) (수정: 4판 리뷰 — 판정을 내부 요청 칸 + 시작 직후 창으로 좁힘)

**이 앱이 요청한 안내(추천 「안내 시작」 · 길안내 입구 · A-01 목적지로 연 안내)는 진행 중 직접 안내로 기억하지 않고, 그 도착도 기록하지 않음(사람 결정).** 이유: 앱 요청 안내는 요청 입구가 이미 핀(안내 시작 기록 · 표준의 `navi_req_log` 에 대응)을 남기고, 장소 행을 만드는 일은 이 이슈 범위(「내비에서 직접 입력」 한정) 밖 · 넓히면 요청 입구의 핀 · 시작 판정과 같은 안내를 두 길에서 기록하게 되어 이중 기록 위험이 생김. 필요하면 별도 이슈(7.1 남은 것).

시작 알림 때 요청 입구의 읽기 전용 질의가 **아래 둘 중 하나일 때만** 「이 앱 요청」(맞음 = 기존 판정 「이름 같음 + 좌표 100 m 안」). 그 밖은 모두 직접 시작.

| 대상 | 이유 |
|---|---|
| (a) 요청 입구의 **내부 요청 칸**(결과 전 요청 · TIMEOUT 뒤 기억 중 — 최대 `AppConfig.TIMED_OUT_REQUEST_MEMORY_MILLIS` 5분)이 목적지 X 로 있음 | 아직 앱 요청의 결과를 기다리는 중 — 이 기능이 시작 알림을 요청 입구보다 먼저 받아도 칸이 남아 있음(F28 · F29) |
| (b) X 가 「시작됨」으로 바뀐 지 `AppConfig.AUTO_RECORD_APP_REQUEST_WINDOW_MILLIS`(60초) 안 — 요청 입구가 기억하는 「마지막으로 시작됨으로 바뀐 장소 + 시각」 한 칸으로 판단 | 요청 입구가 먼저 받아 시작됨으로 바꾸면 내부 칸이 비므로(F29) 그 직후를 덮는 짧은 창 |

- **판정에 쓰지 않는 것**: 상태 흐름에 다음 요청까지 오래 남는 「시작됨(X)」 · 「실패(TIMEOUT · X)」 · 현재 여행의 핀 장소. 셋 다 몇 시간 뒤 사용자가 내비에서 직접 X 를 다시 시작한 경우까지 앱 요청으로 잘못 분류해 그 도착을 빠뜨림(F29 · 2판 · 3판의 핀 · 시작됨 행을 뺀 이유).
- 받는 순서 무관: 요청 입구가 먼저 받음 → 시작됨으로 바뀐 직후라 (b) · 이 기능이 먼저 받음 → 내부 칸이 아직 있어 (a) → 둘 다 앱 요청(T47).
- 요청 입구가 실패(X · TIMEOUT 아님)이거나, TIMEOUT 기억 기한(5분)이 지났거나, 시작됨 뒤 60초가 지난 뒤 사용자가 내비에서 직접 X 를 시작하면 → 직접 안내로 기억 → 그 도착은 기록 대상(핀은 이미 있을 수 있음 · 다른 표).
- 남은 한계(받아들임): ① 앱 요청 X 가 시작된 뒤 60초 안에 사용자가 직접 같은 X 를 다시 시작하면 앱 요청으로 분류(그 도착 기록 안 함 · 현실적으로 거의 없음) ② 앱 요청 X 안내 중 프로세스가 끝나 요청 입구 기억이 사라진 뒤 내비가 같은 X 로 시작 알림을 다시 보내면(재탐색 등 · M3) 직접 시작으로 분류 → 그 도착이 장소로 남아 핀 X 와 장소 X 가 함께 있을 수 있음(드묾 · 같은 여행 안 100 m 중복 판단은 장소끼리만).

### 3.9 위치 동의 철회 때 지우는 것 (수정: 3판 리뷰 — 새 절 · N13 방향 = 비움)

| 대상 | 철회 때 |
|---|---|
| 기록 대기 · 진행 중 직접 안내 | 전부 즉시 삭제 |
| 확정된 자동 장소의 `lat` · `lng` · `addr` | null(기존 철회 그대로) |
| 확정된 자동 장소의 `user_place_nm` | **사람이 고치지 않았으면 null** — 지금 이름이 확정 때 넣은 자동 이름(자동 이름 원본)과 글자까지 같으면 null · 다르면(사람이 A-03 · A-05 · A-08 에서 고침) 남김. 기존 「주소에서 만든 처음 이름」 비교(F13)와 같은 뜻을 자동 이름에 넓힌 것 · 비교는 주소를 지우기 전에 |
| 자동 이름 원본 | 철회 처리 뒤 전부 삭제 |
| 「이어서 쓰기」 칸 | 장소 번호만 있어(F26) 비울 위치 정보 없음 · 그대로 |
| 수동 장소 | 기존 철회 그대로 |

- 자동 이름 원본 = 확정 1건마다 「장소 번호 + 확정 때 넣은 이름」(기기 안 · 4.2 와 같은 꼴) — 이름이 null 로 확정됐으면 남기지 않음. `trip_place_dtl` 칸을 늘리지 않음(N13 비교).
- 「내 기록 모두 지우기」 · 여행 삭제 · 계정 전환 때도 해당 장소의 원본을 지움.
