# Travel Crumbs 밝은 디자인 시스템 및 차량 화면 적용

- 이슈: #82
- 기준 브랜치: `travel-crumbs-theme/main`
- 데이터 표준: v0.55
- 범위: Android Compose 앱 UI와 PLEOS 에뮬레이터 검증

## 목표

제출 영상에 사용할 가족여행 흐름을 실제 PLEOS 에뮬레이터에서 실행할 수 있도록 기존 기능을 보존하면서 전 화면을 따뜻하고 정돈된 여행 기록 도구로 재구성한다. 단순한 색 교체가 아니라 정보 위계, 타이포그래피, 여백, 표면, 형태, 테두리, 상태, 피드백을 함께 변경한다.

## 범위와 비범위

### 적용 범위

- 앱 틀과 내비게이션 레일
- 기록 홈, 여행 시작, 진행 중 기록
- 장소 기록·편집, 여행 종료 확인, 로드맵 검토
- 공개 범위, 내 여행 목록·상세
- 추천·추천 상세·길안내, 설정·동의·공통 팝업
- PARKED, DRIVING, UNKNOWN 상태별 화면 제한
- 실제 PLEOS 에뮬레이터 빌드·설치·화면·기능 검증

### 제외 범위

- 로그인 구현
- 서버, API, DB, Room 모델, 데이터 표준 변경
- Waypoint 모델 또는 UI 도입
- 신규 대형 지도·지도 탐색 기능
- 기존 선형 아이콘 재디자인
- 신규 Gleo 함수 또는 음성 버튼 연결 기능
- `navigation/impl` 변경

## 디자인 방향

### 기본 토큰

| 역할 | 기준 |
|---|---|
| 앱 바탕 | `#FFFCF7` |
| 기본 글자 | `#382C25` |
| 주요 강조 | `#AF5138` |
| 서체 | 저장소의 Asta Sans 자산과 라이선스 재사용 |
| 보조 토큰 | 위 세 색을 기반으로 밝은 표면, 보조 글자, 경계, 선택, 비활성, 성공, 경고, 위험 역할을 분리하며 실제 에뮬레이터 대비를 확인 |

위 세 색은 새 시스템의 출발점이다. 세 값만 기존 테마에 대입한 결과는 완료로 보지 않는다.

### 시각 원칙

- 화면 제목, 섹션 제목, 카드 제목, 핵심 값, 본문, 보조 정보, 버튼의 크기와 굵기를 역할별로 구분한다.
- 큰 글씨와 충분한 여백을 사용하되 PLEOS 앱 영역을 침범하거나 주요 행동이 잘리지 않게 한다.
- 카드, 목록, 칩, 주요·보조·위험 버튼, 팝업을 역할별 형태로 구분한다. 모든 요소에 동일한 둥근 사각형을 반복하지 않는다.
- 배경 없는 버튼은 굵은 실선으로 배경과 구분한다.
- 선택·비활성·누름·집중·처리·성공·오류를 색뿐 아니라 선, 표면, 아이콘, 문구로 함께 표현한다.
- 기존 귀여운 선형 아이콘의 형태와 의미를 유지한다.
- 지도와 목록의 장식 사선 `//`를 제거한다.
- 긴 한글을 개별적으로 축소하지 않고 레이아웃으로 해결한다.

## 공통 컴포넌트

- 주요·보조·위험·아이콘 버튼: Default, Pressed, Focused, Disabled, Loading 상태
- 선택 칩·필터: 선택 표식, 선, 글자 변화 포함
- 카드·목록 행: 정보 위계에 따라 외곽선과 표면을 선택적으로 사용
- 입력·팝업·배너·토스트·처리 표시: 밝은 배경에서 충분한 대비
- 기존 아이콘 의미와 접근성 설명 유지

## 화면 요구

### 앱 틀과 내비게이션

- 「기록」·「내 여행」·「추천」·「설정」 네 항목과 기존 아이콘·레이블을 유지한다.
- PARKED에서는 기존 이동을 허용한다.
- DRIVING과 UNKNOWN에서는 기록 외 정차 전용 화면 선택 시 「정차 후 볼 수 있어요」를 표시한다.
- PLEOS 상단 상태, 왼쪽 Driving View, 하단 차량 제어 영역을 침범하지 않는다.

### 기록 홈과 여행 시작

- 인사말, 여행 시작, 추천, 최근 여행, 근처 로드맵의 우선순위를 재정리한다.
- 여행 시작의 이름, 동행자, 목적지, 위치 동의, 기록 시작 흐름과 저장 의미를 유지한다.
- DRIVING과 UNKNOWN에서는 여행 생성·입력 화면을 노출하지 않는다.

### 진행 중 기록

- 여행 이름, 기록 상태, 기록 시간, 기록 장소 수, 기존 내비 안내 카드를 명확한 위계로 구성한다.
- 기록 지표는 라벨을 위에, 값을 아래에 두고 왼쪽 정렬한다.
- 목표 PLEOS 앱 폭에서 아래 네 행동을 한 줄, 동일 글자 크기로 배치한다.
  - 「이 장소 기록」
  - 「음성」
  - 「기록 일시정지」 또는 「기록 재개」
  - 「여행 종료」
- 네 행동은 중요도와 위험도를 표면·테두리·아이콘으로 구분한다.
- 신규 대형 지도는 만들지 않고 기존 `NaviGuideCard`와 화면 구조를 재구성한다.
- Gleo 음성 명령 실측과 화면의 「음성」 버튼 연결 상태를 구분한다.

### 장소 기록과 로드맵 검토

- PARKED에서 장소 이름, 태그, 메모의 입력·수정을 허용한다.
- DRIVING과 UNKNOWN에서는 임시 기록과 즉시 피드백만 제공하고 상세 입력을 숨긴다.
- 상세 보완이 필요한 Place에만 「기록 필요」를 사용한다.
- 방문 순서는 경로의 작은 순서 원에만 표시한다.
- 장소 유형 아이콘 원에서는 번호를 제거하고 기존 아이콘을 유지한다.
- 같은 방문 번호를 아이콘, 경로, 카드에 중복 표시하지 않는다.
- Waypoint를 추가하지 않고 기존 Place 흐름을 사용한다.
- 기존 `RouteSketch`·`RoadmapMap` 범위 안에서 시각 위계를 재구성한다.

### 종료·공개·내 여행·추천·설정

- 종료 확인의 「계속 기록」과 「종료」를 일반·위험 행동으로 구분한다.
- 공개 범위와 추천 공개 동의, 저장 결과의 기존 의미를 유지한다.
- 실제 서버 공유 완료로 오인할 새 표현을 추가하지 않는다.
- 내 여행 목록·상세의 날짜, 거리, 시간, 장소, 동행자, 공개 상태 우선순위를 정리한다.
- 추천 필터, 지도, 랭킹, 클러스터, 길안내 요청·전달·실제 안내 상태를 그대로 보존한다.
- 설정의 일반 행동과 동의 철회·기록 삭제 위험 행동을 명확히 구분한다.

## 기능 및 데이터 보존

- RECORDING → PAUSED → RECORDING → COMPLETED의 기존 상태 전이를 유지한다.
- 앱 재실행과 포그라운드 복귀 뒤 진행 중 여행과 미완성 입력의 기존 복원을 유지한다.
- SDK 초기화, 서비스 연결, 내비 요청 전달, 실제 내비 시작을 서로 다른 상태로 유지한다.
- 스타일 변경으로 네트워크, 위치 수집, Vehicle SDK 초기화·연결을 새로 유발하지 않는다.
- API, OpenAPI, DB, 인증, 권한, 시드에는 변경이 없다.
- 기어, 속도, VIN, Pleos 토큰, 비밀번호 등 개인정보의 신규 수집·전송은 없다.

## 핵심 검증

1. PLEOS 에뮬레이터에서 밝은 디자인과 Asta Sans가 실제 표시된다.
2. 가족여행 샘플로 여행 시작 → 장소 기록 → 일시정지·재개 → 종료 → 장소 보완 → 저장 → 내 여행 → 추천 → 길안내 흐름을 실행한다.
3. 진행 화면의 지표 정렬과 네 버튼 한 줄 배치를 실제 앱 폭에서 확인한다.
4. Place 상세 보완 상태에만 「기록 필요」가 표시되는지 확인한다.
5. 방문 번호 중복 제거, 유형 아이콘 번호 제거, 장식 사선 제거를 확인한다.
6. PARKED → DRIVING → UNKNOWN → PARKED 전환에서 상세 조작 제한과 복원을 확인한다.
7. 길안내 요청 전달 성공과 실제 안내 시작을 구분한다.
8. Gleo 명령 결과와 화면 「음성」 버튼 상태를 별도로 기록한다.
9. 긴 한글, 선택, 비활성, 처리, 성공, 오류, 팝업의 대비와 잘림을 확인한다.
10. 상단·왼쪽·하단 차량 고정 영역을 침범하지 않는 전체 화면 캡처를 남긴다.

## 완료 조건

- Compose 공통 토큰과 역할별 컴포넌트가 전 화면에 적용되어 있다.
- 정보 위계, 배치, 타입, 간격, 형태, 테두리, 상태, 피드백이 새 방향으로 재구성되어 있다.
- 기존 여행 기록, Place, Gleo, 자동 장소 기록, NaviHelper, 동의, 저장, 복원 기능이 회귀하지 않는다.
- 관련 단위·Compose UI·Lint·Konsist·빌드 검사가 통과한다.
- 실제 PLEOS 에뮬레이터에서 제출 영상 흐름을 실행하고 캡처한다. 정적 목업이나 생성 이미지로 대체하지 않는다.
- 서버 코드, API, DB, 로그인, `navigation/impl`에는 변경이 없다.
