# .claude/log — 이슈별 AI 작업 기록

GitHub 이슈 하나마다 AI 에이전트의 기록을 남깁니다. **AI 활용 기록 공유 · AI 작업 방식 단일화**를 위함입니다.

- 누구나 같은 하네스(이슈 → 오케스트레이터)로 일하고, 로그가 쌓입니다.
- 회고 · `harness:evolve` 의 근거 자료입니다. 「AI 가 어디서 막혔나 · 무엇을 반복했나」를 확인하기 위함입니다.
- 직접 프롬프트로 한 작업은 여기 남지 않기 때문에 기능 · 버그 · 하네스 변경은 모두 이슈로 시작하기를 권장합니다.

## 포맷

```
.claude/log/
  <이슈번호>-<짧은이름>/      ← 예: 5-my-feature · 9-no-sound · 14-log-rule
    log.md                    ← 단계 기록(메인이 단계 끝마다 한 절씩 덧붙임)
    trace.md                  ← 활동 요약(PR 열 때 trace_report.py 출력)
```

- **이름포맷**: 기능은 기능명으로, 버그와 하네스 수정은 브랜치의 짧은이름. 영문 소문자, 숫자, `-`만 사용합니다.

### `log.md`

머릿말(처음 1회):

```markdown
# #<n> <이슈 제목>
- 이슈: https://github.com/<owner>/<repo>/issues/<n>
- 종류: 기능 · 버그 · 하네스 피드백
- 담당: <git user.name>
- 브랜치: <기능명>/main · spec · impl  또는  bug/<n>-… · harness/<n>-…
```

작업 및 단계마다 기록(이슈 댓글과 같은 내용):

```markdown
## <단계> 끝 — <yyyy-mm-dd HH:MM> · <git user.name>
- 산출물: <파일 · 커밋 · PR>
- 에이전트: <부른 에이전트 × 횟수 · 재호출 이유>
- 센서: <명령별 녹색/빨강 한 줄씩>
- 리뷰 지적: <규칙 이름 × 개수 · 센서 후보 표시>
- 막힘: <무엇 · 원인 · 사람 몫인가> 또는 없음
- 사람 결정: <미확정 표 답 · 사용자 지시 요약> 또는 없음
- 다음: <다음 단계 · 누구 몫>
- 활동: <trace_report 요약 첫 줄 — 도구 호출 · 실패 · guard 차단 수>
```

### `trace.md`

PR 을 열 때 `python3 .claude/guardrails/trace_report.py <_workspace 폴더> --flow 15` 출력을 그대로 저장. 원본 `trace.jsonl` 은 `_workspace/`(개인 · gitignore)에 남음 — 크고 명령 원문이 들어 있어 공유하지 않음.

## 규칙

| 무엇 | 규칙 |
|---|---|
| 쓰는 사람 | 오케스트레이터(메인)만. 하위 에이전트 · 사람이 고치지 않음 — 고치면 기록이 아님. 틀린 내용은 다음 절에 「정정」으로 |
| 쓰는 때 | 기능: 1 · 2 · 4 · 6단계 끝 / 버그: 2 · 4 · 6단계 끝 / 하네스 피드백: 반영 끝 · PR 열 때 |
| 커밋 | 그 단계의 작업 브랜치(spec · impl · bug · harness)에 경로 지정 커밋 `docs(log): #<n> <단계>` · 그 단계 산출물과 같은 PR 로 들어감 |
| 7단계 · 마무리 | `<기능명>/main` · develop 에 직접 커밋할 수 없어 이슈 댓글로만 남김 · `log.md` 의 마지막 절은 6단계 |
| 이슈 댓글 | 같은 절 내용을 `gh issue comment` 로도 올림(사람이 알림으로 봄) |
| 넣지 않는 것 | 비밀값 · 토큰 · 개인정보 · 좌표 · VIN · 로그 원문 · 리뷰 표 전문(PR 본문에) |
| 충돌 | 이슈마다 폴더가 달라 없음 · 같은 이슈를 이어서 하면 절을 덧붙임 |
| 지우기 | 지우지 않음 — 회고 자료 |

`.claude/` 의 다른 파일은 하네스 설정이라 `harness/…` 브랜치로만 바뀌지만, `.claude/log/` 는 기록이라 각 이슈의 작업 브랜치에 함께 들어감.
